- 第六阶段：实时中途纠偏（user 说“开始”）。协议不属 ACP 标准，是从两个已安装 bridge 的 dist 源码核实的：扩展请求 `_session/steering`，params `{ sessionId, prompt: ContentBlock[], _meta?: { steering: { idleBehavior } } }`，由 `initialize` 的 `_meta.steering.supported === true` 广告；`codex-acp@2.2.2` 与 `claude-agent-acp@0.93.0` 一致。返回 `outcome`：`injected` / `promptRequired`（Claude 空闲时需显式 opt-in）/ `startedNewTurn` / `failed`（Codex 另有 `noRunningTurn`）。
- 核心危险点：**两个 bridge 在空闲会话上收到 steer 都会自己开一个新 turn**（Codex 无条件，Claude 除非 `idleBehavior:"promptRequired"`）。那样起的 turn 在我们 runtime 里没有 `prompt()` owner，没人 settle/归因/取消。所以：绝不给空闲会话发 steer；收到 `startedNewTurn` 立刻 `session/cancel` 清掉。
- core：`RuntimeSupplementResult`（`injected` | `idle`）、`RuntimeSession.capabilities.supplement`（**协商得来**，getter 暴露，因为 initialize 晚于会话对象创建）+ 可选 `supplement(text, { signal })`；`AcpRuntime` 里 `STEER_ACK_MS=15s` 超时、`advertisesSteering()` 要求显式 true、`failed`/未知 outcome 抛错。`AgentSessionManager.supplement()` 只对 `state === "running"` 的会话投递，返回 `SupplementReport[]`（`injected|idle|unsupported|error`，每 agent 独立，一个失败不影响其他）。
- TUI：`stream:note` action（写 live turn，即使正在回看旧轮次）、`/steer <text>`（`availability: "running"`）、`steerRunningAgents`。语义是“永不丢”：有 agent 收到就写 `[steer] …` 标记 + 提示点名；一个都没收到（没人在轮次中 / bridge 不支持）就**转成排队后续**并说明时机变了；空闲时直接拒绝（否则等于让 provider 自起一个没人认领的 turn）。
- 测试：core AcpRuntime 6 项（含 wire payload 精确断言、空闲不投递、`startedNewTurn` → cancel、未广告 → `supplement:false` 且 reject）+ AgentSessionManager 4 项；dashboard 4 项 Ink 回归（注入/不支持→排队/空报告→排队/空闲拒绝）+ state.test.ts 1 项（note 落 live turn）。**都先临时回退实现确认变红**（4 个 TUI 用例全红）。README 英中补“Steering the turn that is running”与命令表。
