# 2026-10-21

## 诊断:`multiclaw upgrade` 后 `--version` 不变

- 根因两层:
  1. **环境**:本机有两份全局安装 —— pnpm global(`~/Library/pnpm/bin/multiclaw` = 0.4.0,在 PATH 前面)
     与 nvm node v24.18.1 的 npm global(`~/.nvm/.../bin/multiclaw` = 0.5.0)。
     `upgrade` 硬编码 `npm install -g`,写进了 npm 的 prefix,而 PATH 解析到的是 pnpm 的那份。
  2. **代码**:`packages/cli/src/commands/upgrade.ts` 只用 npm,不判断当前二进制属于哪个安装器,
     装完也不校验 PATH 上 `multiclaw` 实际指向哪 —— 于是打印 "Successfully upgraded" 但用户看到旧版本。
## 已修复(同一天)

- 环境:`pnpm rm -g multiclaw` 清掉 0.4.0 的重复安装,`multiclaw --version` → 0.5.0。
- 代码:`upgrade.ts` 重写。核心不变量 —— **升级必须打到"当前正在运行的那一份"所在的 prefix**。
  - `findPackageRoot()` 从 `import.meta.url` 逐级向上找 `package.json.name === "multiclaw"`;
    `detectInstaller(pkgRoot)` 用路径签名判安装器(`/pnpm/global/`、`/.pnpm/` → pnpm;
    `/install/global/`、`/.bun/` → bun;`/yarn/global/` → yarn;`/node_modules/` → npm;否则 unknown)。
  - 只给 npm/pnpm 实现了 `view` + `add -g` 命令对;bun/yarn/unknown 明确报错并给手动命令,
    **不猜**。理由:猜错就又是"装到别处"。registry 查询走安装器自己的 `view`,以尊重 .npmrc 镜像。
  - 装完 `readInstalledVersion(pkgRoot)` 复查(直接 readFileSync,不走 require 缓存),
    与 latest 不符 → 报错退出 1,不再谎报成功。
  - 抽出 `runUpgrade(ctx)` 接受注入的 `exec`/`readVersion`,测试零 mock。
- 测试:22 个,含"装成功但运行副本没变"的回归用例(已临时回退验证会红)。
  `pnpm verify` + cli `test:coverage` 全绿;真机路径签名已验证(npm global → npm,pnpm global → pnpm)。
