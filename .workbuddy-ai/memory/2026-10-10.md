## 新增 PR 质量门禁 CI + typecheck

- 背景:`.github/workflows/` 原本只有 release.yml / bump-version.yml(发布链路),**无任何 push/PR 校验**。
- 新增 `.github/workflows/ci.yml`:push(main)+ pull_request 触发,步骤 install → build → typecheck → test;带 concurrency 取消旧运行。lint 步骤留注释占位(尚未引入 Biome)。
- 各包加 `typecheck` 脚本:`tsc -p tsconfig.json --noEmit`(dashboard 额外跑 `tsconfig.server.json`)。
- 根 `package.json` 加 `typecheck`(=`pnpm -r typecheck`)与 `verify`(=`pnpm -r build && pnpm -r typecheck && pnpm test`)。
- **关键约束:CI 中 build 必须先于 typecheck**——cli/dashboard 的 typecheck 从 core 的 `dist/*.d.ts` 解析跨包类型,clean checkout 下不先 build 会报 TS2307。已验证。
- 验证:`pnpm verify` 全绿(3 包 build + 3 包 typecheck + 52 测试)。

## 环境坑(重要,反复出现)

- pnpm 12 + `node-linker=hoisted` 下,新增包后 `.bin` 软链有时不生成/指向不存在目录,导致 `vitest: command not found`。**再跑一次 `pnpm install` 通常就能修好**(本次重装后 pnpm 正确生成了 `vitest@3.2.7` 与各包 bin)。不要再手工补软链。
- 本机 pnpm store 对 `@biomejs/cli-darwin-arm64` 的 rename 一直失败;但 `pnpm install` 重试后最终仍能落盘。若 biome 报 `Cannot find module`,重装即可。
- 不要在测试运行期间并发跑 `pnpm install`,会因模块解析竞态产生「no tests / 1 error」的假失败。
