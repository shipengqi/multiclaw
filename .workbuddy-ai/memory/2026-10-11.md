## Agent runtime 调用方式的业界调研(用户提问:CLI 调用限制多)
三个研究员分头调研(编码 agent 的编程式调用面 / 多 agent 框架 / 协议与传输),产出英文原始报告
`.workbuddy-ai/reviews/runtime-{cli-agents,frameworks,protocols}.md` 与中文综合
`RUNTIME_RESEARCH.zh-CN.md`(根目录)。

**核心结论**:病灶不是"spawn CLI",而是 `AgentOutput = {output: string; exitCode: number}`
(`types/runtime.ts:13-16`)—— 上游 CLI **早就在发结构化事件**了。
- `claude -p --output-format stream-json` 直接给 NDJSON:`tool_use`/`tool_result`/`usage`/`total_cost_usd`/`session_id`。
  `ClaudeRuntime.ts:26` 只传 `-p --allowedTools`,于是这些全被丢弃。**最小改动 = 换这个 flag。**
- 业界三层:①主流框架(进程内调模型 API,全部暴露结构化事件流,没有读 CLI stdout 的);
  ②唯一直接同类 = **Vercel AI SDK 7 `HarnessAgent`**(`@ai-sdk/harness-claude-code|-codex|-pi`,把 harness 输出
  投影成统一 `fullStream`);③协议各自边界不同:**MCP=模型↔工具**、**ACP=客户端↔编码 agent(multiclaw 的正确边界)**、
  A2A=agent↔agent(远端)、AG-UI=agent↔前端。
- `AgentRuntime` 收敛形状(ACP / Claude Agent SDK `Transport` / OpenHands `Runtime` 四者一致):
  **能力协商 + 类型化事件流 + session + 权限回调 + 可插拔 transport**。
- **`AgentRuntime` 是已发布包的导出 → 加宽是破坏性变更,必须在第二个 runtime 发布前做。**

**交叉点**:`AgentRuntime` 无 session ↔ 评审发现 1(ask 环路缺 session 缝),同一病根;
`checkAvailable()` 重复检查在 `run.ts:32` / `tui.ts:19`,与 `describe()` 一起落地。

**注意**:部分官方文档站 JS 渲染抓不到,研究员用镜像/raw 文件,报告里已标注低置信项
(Codex `codex-app-server`、Gemini `--allowed-tools`、OpenHands resume 语义、A2A v1.0 日期),实现前需回一手文档复核。

- 真实 API(读自安装后的 `dist/acp.d.ts`,非记忆):`client(options?)` → `ClientApp.connectWith(stream, ctx => …)`;
