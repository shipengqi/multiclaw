### 可复用经验

- **"看板算可用"和"执行时可用"是两回事。** `commands.ts` 的 `availability`（注释写明 "When a command may be
  run"）**只在面板的候选列表里生效**；`submit()` → `runCommand` 从不校验。于是把命令逐字打出来再回车
  就绕过了整套阶段规则——运行中打 `/replay` 会覆盖 `abortRef.current`（丢掉在跑的 controller，
  `ctrl+c` 再也停不下那轮）、`dispatch turn:start` 覆盖在屏轮次、并在同一 workDir 起第二个 Orchestrator。
  `/retry` 自 Batch 3 起就有同一个洞。**这是本轮第四个"声明了契约、代码不履行"**（前三个：F1 块预算、
  F4 条目预算、C12 `resolveArgs`）。收口在唯一派发点 `runCommand` 顶部，复用 `availableCommands` 不新增第二套定义。
- **未提交的工作 ≠ 不存在的工作。** 工程方 429 限流前做完了活但没 commit，我第一次看 `git log` 就断定没做。
  同理，我先前的 BSD `grep 'a\|b'` 又静默匹配为空（本批第三次，`\|` 在 BSD grep 里不是 alternation）。
  **判据：用 `git diff` / `git status` 看工作树，不要用 `git log` 推断"有没有做"；模式匹配一律用 Grep 工具。**
- **`git checkout -- <file>` 会把未提交的修复抹掉**（它从 HEAD 恢复）。探针前先 `git diff > /tmp/x.patch`
  存档，探针后 `git apply --include=<file>` 定点恢复。我这次就踩了，靠 patch 捞回来。
